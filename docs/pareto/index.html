Batch and memory limits

Batches hold 36 MiB of float32 output and lookahead holds 144 MiB at every crop size. CPU input buffers hold 256 chunks. These limits give batches of 576, 256, and 144 samples at 128², 192², and 256² respectively.

What was measured: two machines, one storage setup per machine

The November 6, 2026 studies contain 93 settings and 387 executions. Every timed pass began with zero resident shard-data pages. Warmup, initialization, and cache clearing are outside the timer; reading, decoding, and final GPU completion are inside it.

H100 node: Intel Xeon Platinum 8462Y+ and one H100 80 GB. EPYC node: AMD EPYC 9655P. Each used 32 allowed logical CPUs, 16 file workers, and 16 CPU decode workers, with XFS on its own array of eight 7.68 TB Intel drives. Exact inventories and idle activity are in the explorer.

EPYC measurements were noisier: median min–max spread 11.3%, versus 1.7% on the H100 node. Ranges describe three observations, not confidence intervals. Random arrays have 16 spatial shards per source; baked samples use 16 files total. Shards target about 1 GiB uncompressed. Full protocol, sources, and reproduction.

Reading the measurements

Image throughput
Requested image bytes delivered per second, counted in the source data type. Converting uint16 to float32 does not increase this number.
Compression ratio
Uncompressed image bytes in the stored arrays divided by their file bytes. Larger values mean less storage is needed.
Storage bandwidth
Read bytes per second recorded by Linux for the storage system. This includes any extra reads needed to deliver the requested pixels.
IOPS
Completed read operations per second recorded by Linux for that same storage system. One file read request can produce several storage operations.
Storage work per sample
Storage bytes or completed read operations divided by the number of delivered crops in each execution. Lower values mean less storage work for the same crop size. One operation can serve multiple samples.

Image throughput and storage bandwidth use GiB/s, where 1 GiB is 2³⁰ bytes. IOPS uses reads/s. All rates use elapsed measurement time, including reading, decoding, and final GPU completion. Initialization, warmup, and cache clearing are excluded. The Storage system section identifies the shared hardware; Diagnostics contains reader-level counters.

Measurement limits

The observed frontier compares settings within the same input, crop size, read pattern, backend, machine session, and storage condition. Filters recompute it. Connections join measured points; they do not predict unmeasured settings. All compared panels use the same axes.

Ranges are observed minima and maxima, not confidence intervals. Use the measurements table or keyboard to select overlapping points. This is a reduced parameter sweep; unmeasured settings may perform better.

Compression ratio includes padding, shard indexes, and array metadata. Mixed studies use expanded, tiled source distributions. A ratio below one means the files are larger than the uncompressed image bytes. The compression axis is logarithmic.

Every timed pass starts with zero resident data-file pages; codecs and metadata are warmed. Overlapping reads and read-ahead within each pass are included. Storage counters include other activity on the same drives. Idle measurements are available in Diagnostics, and SSD/controller caches are not controlled.
