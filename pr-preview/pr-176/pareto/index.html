Reading the measurements

Useful throughput counts the pixels requested by the read, in their source data type, divided by elapsed time. Converting uint16 pixels to float32 does not increase this rate. GPU measurements wait for the final device work to finish. Initialization and warmup are separate.

Compression divides the original image bytes by stored Zarr file bytes, including padding, shard indexes, and array metadata. The horizontal axis is logarithmic. Values below one mean the stored files are larger than the original image.

Application requests/s counts data reads after adjacent requests are combined, divided by elapsed time. Encoded bandwidth counts the bytes in those requests. Metadata reads are separate. Higher request rates can mean smaller reads, so the plot includes encoded bandwidth and the details show average request size. Application requests are distinct from filesystem, NFS, and NVMe operations.

A setting is on the observed frontier if no other tested setting in the same input, read pattern, backend, machine session, and storage condition is at least as good on both axes and better on one. Filters recompute that frontier. Raw controls remain in the comparison when filtering Blosc blocks. Connections join observations; they do not interpolate unmeasured performance.

Ranges are observed minima and maxima, not confidence intervals. Reference variation describes the bracketing control runs. Pilot studies cover a limited set of settings and establish measurement cost and repeatability; they do not establish a final frontier.

Preloaded files measure the reader with a small, cached image working set. Overlapping or repeated requests can share encoded reads, so read amplification can be below one even without compression. These rates do not establish disk or network bandwidth. Shard geometry and CPU worker counts are held fixed within a study. Stage intervals overlap and must not be added into an elapsed-time breakdown.

Cold studies verify local PCIe NVMe storage, clear each data file from the Linux page cache after warmup and before every timed batch, and verify zero resident pages. Cache clearing is excluded from time. NVMe counters cover the devices as a whole, including other jobs and readahead; details retain adjacent idle traffic. These small, repeated cold batches do not establish sustained streaming performance or control SSD/controller caches.
